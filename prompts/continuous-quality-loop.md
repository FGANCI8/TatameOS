# Continuous Quality Loop

## Purpose
Describe the operating cycle that keeps the system improving safely.

## Cycle
1. Detect
2. Classify
3. Correct
4. Validate
5. Record
6. Monitor

## Rules
- Every detected issue must be classified.
- Every correction must be validated.
- Every validation failure must be recorded.
- Every recurring signal must re-enter the loop.

## Signals that enter the loop
- Bugs
- Friction
- UX confusion
- Release failures
- Tenant leakage risk
- Performance regressions
- Silent errors

## Principle
Quality is not a one-time event; it is a loop with evidence.
